Recovering Homographies

   
       

           For image alignmen the projective transformation between photos needed to be recovered. This transformation is a Homography, which is a a 3x3 matrix \(H\) w/ 8 degrees of freedom. The last element is a scaling factor normalised to 1. The relationship betwee point \(p\) in one image and its corresponding point \(p'\) in another is given by: \(p' = Hp\).        

       

Using DLT & SVD

       
           

                I used DLT, so given a set of corresponding points (same places in the overlap of two images) \((x, y)\) and \((x', y')\),up a system of linear equations \(Ah = 0\), where \(h\) is a vector containing the 9 elements of \(H\) can be made. Thus, frome each set of points from the same place (a correspondence) I got two equations, forming two rows in the matrix A:            

           
                $$                 \begin{bmatrix}                 x & y & 1 & 0 & 0 & 0 & -x'x & -x'y & -x' \\                 0 & 0 & 0 & x & y & 1 & -y'x & -y'y & -y'                 \end{bmatrix}                 h = 0                 $$            
           

                A minimum of 4 points (8 equations) are required. For improvemtns against noise, I use more point, (the returns were extremely diminishing after 6 points), to get a overdetermined system. The leasat squared solution which minimizes \(||Ah||\) with SVD. The solution \(h\) is the eigenvector which represents the smallest singular value of \(A\).

Part B: Auto Feature Matching and Mosaicing

   
     

        In A i had to manuallt selecting points, which is is not only error pront (but was insanely monotonous and tedious). Now B I made pipeline based on the paper "Multi-Image Matching using Multi-Scale Oriented Patches".      

     

        My main classes for new pipeline were:      

     
           
  • FeatureDetector: Which has Harris Corner detection and Adaptive Non-Maximal Suppression (ANMS).
    •        
  • FeatureDescriptorExtractor: Thhis gets the normalized 8x8 descriptor from a 40x40 window for each feature point.
    •        
  • FeatureMatcher: Matches features between two images using SSD calculation, and ussing Lowes ratio test.
    •        
  • RansacHomographyEstimator: Uses RANSAC to determine best homography within or given rather the noisy set of possible matches.
    •      
   
   

B.1: Harris Corner Detection and ANMS

   
     

        First, points of interest are gotten with Harris Corner algorithm.FeatureDetector computes the harmonic mean Harris response (followed from the apepr) and finds all local maxima above a threshold. Just from this I get on the order of tens of thousands of points of interest.      

     

        To work with less points, and have them more satially seperated, I apply Adaptive non Maximal Suppression (ANMS). This alg, implemented in my ANMS method, sorts the points by strength, and then finds the min suppression radius for every point. THen i keep keeping the top 500 points with the largest respective suppression radius. This, I now have a good distribution of strong features across the image,rather than dense clumps in one area.      

   
   
               
   

B.2 & B.3: featrue descriptors and matchin

   
     

        Given a good set of feature points, a descriptor is extracted. Like the spec outlined, my FeatureDescriptorExtractor takes a 40x40 window around each point, blurs it to prevent aliasing, and then samples down to an 8x8 rea. Then, I take the area and ensure that it gets bias/gain normalized so that light changes don't affect it. Then I end up with a This 64-dimensional vector which is the features fingerprint.      

     

        The FeatureMatcher class then finds tentative matches. It gets SSD between all descriptors in image 1 and image 2. For every feature the two nearest neighbors NN1, and NN2 are found. Then with Lowe's ratio test, any match is kept iff the ratio SSD(NN1)/ SSD(NN2) is below a threshod--which from looking at the paper I chose 0.6. This filters out ambiguous matches, where a feature is similar to myraid otehr ones.      

   
   
               
   

A Note on False Matches

I believe this happened because the feature descriptors are not perfectly unique. Repetitive like paint and metal edges and the hallway compared to metal edgess simply produce descriptors that are mathematically very similar just by coincidenc. Although, there were far less matches in this example, which empahsies the point on having robust filtering step.    

   

B.4: RANSAC for Homography

   
     

        Still, tehre is a set of tentative matches which is noisy and has many outliers (like the false matches that I jsut mentioned prior). For the true geometric transformation, I used RANSAC (Random Sample Consensus), in my RansacHomographyEstimator class      

     

        This algorithm works as follows:      

     
           
  1. Sample: At random, select 4 correspondence points from the tentative matches.
    2.        
  2. Then, compute: a candidate homography matrix \(H\) from the 4 points
    3.        
  3. Score: Project all points from img1 into img2 with the \(H\). Then count up the number of inliers. Inliers are points where the projected location is within a pixel threshold (5 pixels for example) of the matched location in image 2.
    4.        
  4. Repeat: This happens for many iterations. The \(H\) that produces the largest set of inliers is naturally the deeted best model.
    5.        
  5. Refinement: A new, more accurate homography is computed using all the inliers from the best model.
